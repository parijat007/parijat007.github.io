Security of this site

The site is built on the assumption that any part of it could be attacked. So every build is signed in a public log, and every brief is recorded in a chain that cannot be rewritten without it showing.

Check it yourself

Three checks, each needing only public data. They run every hour as well, with an alert if any fails.

  1. The build is signed. build.json lists the fingerprint of every file on the site. Each deploy signs it through Sigstore, whose public transparency log cannot be edited. With the GitHub CLI:
    gh attestation verify build.json -R {{ repo }} --signer-workflow {{ repo }}/.github/workflows/pages.yml
  2. The files match the build. The SHA-256 of any page you download should equal its entry in build.json.
  3. The record is unbroken. build.json carries the head of the brief record. That head must appear in ledger.jsonl, and the chain must check out:
    python -m digest.ledger verify in a copy of the source.

What protects it

  • No server, no accounts, no trackers. The site is static files. There is nothing to log in to and no personal data is stored.
  • Strict content policy. Pages load scripts only from this site, and the policy is checked daily.
  • Untrusted text stays data. Feed text is cleaned before any model reads it, and risk facts (KEV, EPSS, SSVC, CVSS) come from the sources, never from a model.
  • Locked supply chain. Every build step is pinned to an exact version, and Python packages are installed only if their fingerprints match.
  • Continuous checks. Secret scanning, dependency audit, code scanning and workflow linting on every change; tests must pass before anything deploys.
  • Copies kept elsewhere. The full history is backed up weekly, including a copy held off GitHub.
